# MVP 产品需求说明

MVP 是“最小可用版本”的意思。它不是最终完整产品，而是先做一个小而清楚的版本，用来验证核心流程是否可行。

本项目第一版的核心流程是：

用户注册登录后，获得或拥有一定积分，输入文字提示词提交视频生成任务。系统扣除或冻结积分，把任务交给线上 GPU 服务器生成视频。生成完成后，用户可以在网页里播放自己的视频，并看到历史记录。

## 1. 用户角色

### 普通用户

普通用户可以：

- 注册账号。
- 登录账号。
- 查看自己的积分余额。
- 输入一段文字提示词。
- 提交一个视频生成任务。
- 查看任务状态。
- 播放自己生成成功的视频。
- 查看自己的视频历史记录。

### 管理者

第一版管理者只需要能通过后台数据或简单管理方式了解系统情况。暂时不要求开发完整管理后台。

管理者后续可能需要查看：

- 用户数量。
- 任务数量。
- 失败任务。
- GPU 服务器运行情况。
- 云存储使用量。

## 2. 用户注册与登录

第一版需要支持：

- 用户注册。
- 用户登录。
- 用户退出登录。
- 登录后才能提交视频生成任务。
- 每个用户只能看到自己的任务和视频。

第一版可以优先选择成熟、简单的登录方案，不追求复杂权限系统。

## 3. 积分系统

每个用户有一个积分余额。

第一版需要支持：

- 查询当前用户积分。
- 提交任务前检查积分是否足够。
- 积分不足时拒绝提交任务，并提示用户。
- 任务提交成功后记录积分变化。

第一版暂时不做：

- 在线支付。
- 邀请奖励。
- 比特币奖励。
- 复杂积分活动。

积分扣除规则可以先采用简单规则，例如：生成一个 5 秒视频消耗固定积分。具体数值后续再定。

## 4. 视频生成任务

用户提交任务时，需要提供：

- 一段文字提示词。

系统自动固定：

- 视频时长：5 秒。
- 视频模型：只使用一个指定开源模型。
- 输出清晰度：暂定 480P 或 720P。
- 每次只提交一个任务。

第一版暂时不支持：

- 上传参考图片。
- 多提示词批量生成。
- 多模型选择。
- 自定义视频长度。
- 自定义复杂参数。

## 5. 任务状态

任务需要是异步任务。异步的意思是：用户提交任务后，不需要一直卡在同一个请求里等待视频生成完成。

第一版任务状态包括：

- 等待中：任务已经提交，正在排队。
- 生成中：GPU 服务器正在生成视频。
- 成功：视频已经生成完成，并保存到云端存储。
- 失败：任务生成失败，需要记录失败原因。

网页需要让用户能看到这些状态变化。

## 6. GPU 服务器

第一版计划使用线上 RTX 5090 GPU 服务器。

GPU 服务器负责：

- 接收后端派发的视频生成任务。
- 运行开源视频生成模型。
- 在 32GB 显存内完成 5 秒视频生成。
- 把生成结果上传到云端存储。
- 把任务结果回传给后端。

第一版暂时不做自动 GPU 扩缩容，也不支持大量用户同时生成。

## 7. 视频存储与播放

生成成功的视频需要保存到云端存储。

系统需要保存：

- 视频文件地址。
- 视频所属用户。
- 视频对应的提示词。
- 任务状态。
- 创建时间。
- 完成时间。

用户在网页中只能播放自己的视频。

第一版为后续下载功能做准备，但暂时可以不提供下载按钮。

## 8. 安全与边界

第一版必须遵守：

- 用户笔记本只用于开发和管理，绝不作为公开服务器。
- 密钥、密码、访问令牌不能写入源代码。
- 不连接真实云服务，除非后续明确进入部署阶段。
- 不虚构已经完成的功能。
- 不自行添加支付、邀请、比特币奖励、设备指纹等功能。
- 不删除或修改用户电脑中的其他文件。

## 9. 第一版验收标准

当真正进入功能开发后，第一版可以按下面标准验收：

- 用户可以注册、登录、退出。
- 登录用户可以看到自己的积分。
- 积分不足时不能提交任务。
- 积分足够时可以提交一个文字到视频任务。
- 任务有清楚的状态变化。
- GPU 服务器可以处理任务并返回结果。
- 视频生成完成后可以被保存和播放。
- 用户可以看到自己的视频历史记录。
- 普通用户不能看到别人的视频。
